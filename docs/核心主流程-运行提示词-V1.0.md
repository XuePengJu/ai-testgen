| 阶段 | 断言要点 |

## 三、常见问题

| 症状 | 处理 |
|---|---|
| 用例收集不到 / 被跳过 | 这条挂了 `@slow`，默认 `addopts` 排除了它，必须显式 `-m "slow"`（命令行 `-m` 会覆盖 `addopts` 的 `-m`） |
| 一段 webm 都没有，用例全 failed 且 teardown ERROR | 漏了 `--tracing=off` |
| 卡在 ⑤ 很久 | 正常需要等真实大模型生成（实测 90–180 s，历史最慢 401.9 s）。用例已内置「检测到失败立刻报错」，不会再黑等几十分钟 |
| 报 `任务生成失败（用例库行：… 失败）` | 后端真的把任务标 failed 了。按「如果失败」那三步取证据，去 `logs/app.log` 找 `工作流步骤失败` 的堆栈 |
| 任务卡在「生成中」不动 | 先看 `logs/app.log` 有没有 `用例解析无产出`；再看模型池当前文本模型是否抽风 |
| 导出断言失败、下载 0 字节 | 检查 `/api/tasks/<id>/download?fmt=xlsx|json|xmind` 的后端实现与 `task.cases_json` 是否有内容 |
| 生成的用例条数明显偏少 | 平台池文本模型会切换；模型抽风时 `llm_usage` 里会出现 `ok=1 & completion_chars=0` 的记录 |
