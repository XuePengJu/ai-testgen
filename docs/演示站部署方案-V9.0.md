# 演示站部署方案（V9.0 · 子路径反代 · 单项目双实例）

## 一、架构总览

```
                          https://ai-testgen.agentest.vip
                                      │
                              Nginx (443)
                        ┌─────────────┴─────────────┐
        location /                    location /demo/  (rewrite 去前缀)
                        │                           │
                 ┌──────▼──────┐            ┌──────▼──────┐
                 │  ai-testgen │            │ai-testgen-  │
                 │ .service    │            │demo.service │
                 │  8005       │            │  8006       │
                 └──────┬──────┘            └──────┬──────┘
                 .env.prod（MySQL 生产库）    .env.demo（SQLite 独立库）
                 AITF_DEMO_ENABLED=0         AITF_DEMO_ENABLED=1
```

- **一份代码库**（Git 仓库 ai-testgen），两个 systemd 服务实例。
- **两个进程完全隔离**：不同端口、不同配置、不同数据库、不同 JWT_SECRET。
- **后端零感知前缀**：Nginx 把 `/demo/` 前缀 rewrite 掉，演示站后端看到的仍是裸路径。
- **前端需补前缀（关键）**：浏览器侧的绝对路径 `/api` **不会**经过反向代理的
  rewrite，会绕过 `/demo/` 命中 `location /` 打到正式站 8005（读写生产数据）。
  因此演示站后端在 index.html 注入 `window.__AITF_API_BASE__="/demo"`，
  前端所有请求出口（`api()` / `apiJson()` / SSE / 文件下载 / 登录注册）统一经
  `withBase()` 补前缀（见 `frontend/src/api/client.ts`）。
  正式站不注入该变量 → 基址为空串 → 行为与改造前完全一致。

## 二、数据库隔离（关键）

| 维度       | 正式站                    | 演示站                                   |
|------------|--------------------------|------------------------------------------|
| 配置文件   | `.env.prod`              | `.env.demo`                              |
| DB_TYPE    | mysql                    | sqlite                                   |
| 数据库     | MySQL `ai-testgen` 库    | `/root/ai-testgen-demo/app.db`（独立目录）|
| 文件/向量  | `/root/ai-testgen/{uploads,outputs,vectors}` | `/root/ai-testgen-demo/...`（随 AITF_ROOT_DIR 隔离） |
| JWT_SECRET | 生产密钥                  | `demo-only-secret-key-...`（必须不同）    |
| 每日重置   | 无                        | 02:00 自动清空业务数据 + 重播种           |

**关键机制**：`.env.demo` 里设 `AITF_ROOT_DIR=/root/ai-testgen-demo`，
`config.py` 的 `DB_PATH = _ROOT/"app.db"` 自动变成
`/root/ai-testgen-demo/app.db`，与正式站 `app.db` 物理分离。
同时 `uploads/ outputs/ vectors/` 也全部随 `_ROOT` 隔离 —— 演示站的数据
（含 Chroma 向量库）与正式站**完全物理隔离**，互不可见、互不污染。

## 三、部署步骤

### 1. 服务器放置配置

```bash
# 演示站独立数据目录（首次）
mkdir -p /root/ai-testgen-demo

# .env.demo 放项目根（已在 .gitignore，需在服务器上单独创建，含独立 JWT_SECRET）
# 关键项（完整模板见本地 .env.demo）：
#   AITF_DEMO_ENABLED=1        # 演示模式开关
#   AITF_DEMO_BASE_PATH=/demo  # 必须与 Nginx location 前缀一致
#   AITF_ROOT_DIR=/root/ai-testgen-demo
#   DB_TYPE=sqlite
#   JWT_SECRET=<openssl rand -hex 32>   # 必须与正式站不同
#   DASHSCOPE_API_KEY=<从 .env 复制>     # 演示站可真实生成（DB 模型池为空时走 env 兜底）
```

### 2. systemd 服务（/etc/systemd/system/ai-testgen-demo.service）

```ini
[Unit]
Description=AI TestGen Demo (V9.0 演示站)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/ai-testgen
Environment=AITF_ENV_FILE=/root/ai-testgen/.env.demo
ExecStart=/root/ai-testgen/venv/bin/uvicorn main:app --host 127.0.0.1 --port 8006
Restart=always
RestartSec=3
# 重置任务要写库 + 清文件，给足时间
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now ai-testgen-demo
systemctl status ai-testgen-demo
```

### 3. Nginx（ai-testgen.agentest.vip.conf 增加 /demo location）

```nginx
# 正式站（保持原有）
location / {
    proxy_pass http://127.0.0.1:8005;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

# 演示站：/demo 子路径 → 8006，rewrite 去掉前缀
location /demo/ {
    proxy_pass http://127.0.0.1:8006;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    rewrite ^/demo/?(.*)$ /$1 break;
    # SSE 流式响应：与正式站一致，关缓冲 + 拉长超时
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
    client_max_body_size 50m;
}
# 根入口 /demo（无尾斜杠）也重写，避免 404
location = /demo {
    return 301 /demo/;
}
```

> ⚠️ `proxy_pass` **不带 URI**（`http://127.0.0.1:8006;`），配合 rewrite break 精确去前缀；
> 若 `proxy_pass http://127.0.0.1:8006/;`（带 `/`）则会把整个 URI 替换为 `/`，路由全丢。
>
> ⚠️ 静态资源（`/assets/*.js`）由 `location /` 走正式站 8005 返回 —— 两个实例
> 共用同一份 `frontend/dist`，文件完全一致，无副作用。

验证：
```bash
nginx -t && nginx -s reload
curl -s https://ai-testgen.agentest.vip/demo/api/demo/meta   # 演示站 meta（is_demo=true）
curl -s https://ai-testgen.agentest.vip/health               # 正式站
curl -s https://ai-testgen.agentest.vip/demo/ | grep __AITF_API_BASE__   # 应输出 "/demo"
```

### 4. 本地联调（沙箱内）

```bash
# 终端 1：正式站（MySQL 或 sqlite 均可）
AITF_ENV_FILE=.env.prod uvicorn main:app --port 8005

# 终端 2：演示站（独立 sqlite 库）
AITF_ENV_FILE=.env.demo uvicorn main:app --port 8006

# 验证
curl -s http://127.0.0.1:8006/api/demo/meta       # {"is_demo": true, ...}
curl -s -X POST http://127.0.0.1:8006/api/demo/token  # admin token（明文通道）
```

### 5. 初始知识库快照（V9.4 —— 否则每天 02:00 重置后知识库又是空的）

每日重置调用 `purge_user_data` 会**连 global 共享知识库一起清空**（这是正确语义：
演示用户造的数据每天归零）。为了让演示站每天都有可浏览/检索的示例知识库，
采用「快照回灌」机制：

```bash
# ① 在源实例导出快照（含 DB 行 + 原始文件 + 真实向量，无需重算 embedding）
.venv/bin/python scripts/export_kb_snapshot.py \
    --out /tmp/demo-kb-snapshot \
    --base <ERP知识库id> --base <admin个人库id>

# ② 打包上传到演示站数据目录（快照目录随 AITF_ROOT_DIR 隔离）
tar -C /tmp -czf - demo-kb-snapshot | ssh root@<server> \
    'mkdir -p /root/ai-testgen-demo/seed && tar -C /root/ai-testgen-demo/seed -xzf - --strip-components=1'

# ③ .env.demo 配置（见下），然后首次播种（幂等，可反复执行）
AITF_ENV_FILE=/root/ai-testgen/.env.demo /root/ai-testgen/venv/bin/python scripts/seed_demo_kb.py
```

`.env.demo` 新增两项：

```bash
AITF_DEMO_KB_SEED_DIR=/root/ai-testgen-demo/seed   # 快照目录（空=不恢复）
AITF_DEMO_KB_OWNER_USER_ID=2                       # 快照库归属账号 id（演示站 admin）
```

机制说明：

- 快照 = `meta.json` + `bases/docs/chunks/revisions.json` + `files/` + `vectors.json`
- 回灌动作（`app/services/demo_kb_seed.py`）：按主键补行（幂等）、把原始文件还原到
  演示站 `uploads/knowledge/<kb_id>/`、向量走 `vectorstore.upsert_raw_vectors()`
  直接写入（**不调用 Embedding 服务** —— 演示站没有 embedding key 也能恢复）
- 重置链路：`demo_reset.reset_demo_data()` 在「清空 → 重播种示例任务」之后调用
  `seed_demo_kb_from_config()`，失败只记 WARNING，不影响重置其余部分
- 检索降级：演示站未配 Embedding 时，`vectorstore.search()` 在演示模式下把稠密
  通道置空（正式站仍是显式报错），检索由 BM25 稀疏通道兜底 —— 关键词检索可用；
  后续配了 embedding key，快照里的真实向量立刻参与语义排序，无需重建索引

## 五、安全注意事项

1. **JWT_SECRET 必须不同**：演示站用独立 secret，token/会话密钥与正式站双向隔离。
2. **演示站绝不连正式 MySQL**：`.env.demo` 里 `DB_TYPE=sqlite` 且未配 DB_* 字段，
   db.py 只会在 `DB_TYPE == "mysql"` 时走 MySQL —— 双保险。
3. **Banner 注入只发生在演示实例**：`index()` 检查 `AITF_DEMO_ENABLED`，
   正式站返回的 HTML 与原来完全一致。
4. **/api/demo/* 在正式站一律 403**：`_require_demo_enabled()` 按进程级开关拦截。
5. **重置是后台任务**：任一步失败只记日志不抛异常，调度器不会崩。
