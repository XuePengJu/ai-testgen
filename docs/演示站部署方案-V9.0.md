# 演示站部署方案（V9.0 · 子路径反代 · 单项目双实例）

## 一、架构总览

```
                          https://ai-testgen.agentest.vip
                                      │
                              Nginx (443)
                        ┌─────────────┴─────────────┐
        location /                    location /demo/  (rewrite 去前缀)
                        │                           │
                 ┌──────▼──────┐            ┌──────▼──────┐
                 │  ai-testgen │            │ai-testgen-  │
                 │ .service    │            │demo.service │
                 │  8005       │            │  8006       │
                 └──────┬──────┘            └──────┬──────┘
                 .env.prod（MySQL 生产库）    .env.demo（SQLite 独立库）
                 AITF_DEMO_ENABLED=0         AITF_DEMO_ENABLED=1
```

- **一份代码库**（Git 仓库 ai-testgen），两个 systemd 服务实例。
- **两个进程完全隔离**：不同端口、不同配置、不同数据库、不同 JWT_SECRET。
- **前端零感知**：Nginx 把 `/demo/` 前缀 rewrite 掉，演示站后端看到的就是裸路径；
  所有 `/api` 请求天然落在演示站进程上。

## 二、数据库隔离（关键）

| 维度       | 正式站                    | 演示站                                   |
|------------|--------------------------|------------------------------------------|
| 配置文件   | `.env.prod`              | `.env.demo`                              |
| DB_TYPE    | mysql                    | sqlite                                   |
| 数据库     | MySQL `ai-testgen` 库    | `/root/ai-testgen-demo/app.db`（独立目录）|
| 文件/向量  | `/root/ai-testgen/{uploads,outputs,vectors}` | `/root/ai-testgen-demo/...`（随 AITF_ROOT_DIR 隔离） |
| JWT_SECRET | 生产密钥                  | `demo-only-secret-key-...`（必须不同）    |
| 每日重置   | 无                        | 02:00 自动清空业务数据 + 重播种           |

**关键机制**：`.env.demo` 里设 `AITF_ROOT_DIR=/root/ai-testgen-demo`，
`config.py` 的 `DB_PATH = _ROOT/"app.db"` 自动变成
`/root/ai-testgen-demo/app.db`，与正式站 `app.db` 物理分离。
同时 `uploads/ outputs/ vectors/` 也全部随 `_ROOT` 隔离 —— 演示站的数据
（含 Chroma 向量库）与正式站**完全物理隔离**，互不可见、互不污染。

## 三、部署步骤

### 1. 服务器放置配置

```bash
# 演示站独立数据目录（首次）
mkdir -p /root/ai-testgen-demo

# .env.demo 放项目根（不进 git 也行，服务器直接编辑）
cp /root/ai-testgen/.env.demo /root/ai-testgen/.env.demo
```

### 2. systemd 服务（/etc/systemd/system/ai-testgen-demo.service）

```ini
[Unit]
Description=AI TestGen Demo (V9.0 演示站)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/ai-testgen
Environment=AITF_ENV_FILE=/root/ai-testgen/.env.demo
ExecStart=/root/ai-testgen/.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8006
Restart=always
RestartSec=3
# 重置任务要写库 + 清文件，给足时间
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now ai-testgen-demo
systemctl status ai-testgen-demo
```

### 3. Nginx（ai-testgen.agentest.vip.conf 增加 /demo location）

```nginx
# 正式站（保持原有）
location / {
    proxy_pass http://127.0.0.1:8005;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

# 演示站：/demo 子路径 → 8006，rewrite 去掉前缀
location /demo/ {
    proxy_pass http://127.0.0.1:8006;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    rewrite ^/demo/?(.*)$ /$1 break;
}
# 根入口 /demo（无尾斜杠）也重写，避免 404
location = /demo {
    return 301 /demo/;
}
```

> ⚠️ `proxy_pass` **不带 URI**（`http://127.0.0.1:8006;`），配合 rewrite break 精确去前缀；
> 若 `proxy_pass http://127.0.0.1:8006/;`（带 `/`）则会把整个 URI 替换为 `/`，路由全丢。

验证：
```bash
nginx -t && nginx -s reload
curl -s https://ai-testgen.agentest.vip/demo/health      # 演示站
curl -s https://ai-testgen.agentest.vip/health           # 正式站
```

### 4. 本地联调（沙箱内）

```bash
# 终端 1：正式站（MySQL 或 sqlite 均可）
AITF_ENV_FILE=.env.prod uvicorn main:app --port 8005

# 终端 2：演示站（独立 sqlite 库）
AITF_ENV_FILE=.env.demo uvicorn main:app --port 8006

# 验证
curl -s http://127.0.0.1:8006/api/demo/meta       # {"is_demo": true, ...}
curl -s -X POST http://127.0.0.1:8006/api/demo/token  # admin token（明文通道）
```

## 四、行为验证清单

| 场景 | 预期 |
|------|------|
| 访问 `https://ai-testgen.agentest.vip/demo/` | 顶部出现蓝色「演示站 · 每日 02:00 自动清空」Banner，免登录直接以 admin 身份进入 |
| Banner 右侧「前往正式站 →」 | 新窗口打开 `https://ai-testgen.agentest.vip` |
| 访问 `https://ai-testgen.agentest.vip/` | 无 Banner，正常登录流程（guest 静默/登录弹窗） |
| `POST /api/demo/token`（正式站） | 403（AITF_DEMO_ENABLED=0）|
| 凌晨 02:00 | 日志出现「演示站每日重置开始/完成」，库内业务表清零，示例任务重新播种 |
| `POST /api/demo/reset`（演示站 admin） | 立即重置，返回 counts |
| 演示站改密码/建任务 | 不影响正式站任何数据（双库物理隔离）|

## 五、安全注意事项

1. **JWT_SECRET 必须不同**：演示站用独立 secret，token/会话密钥与正式站双向隔离。
2. **演示站绝不连正式 MySQL**：`.env.demo` 里 `DB_TYPE=sqlite` 且未配 DB_* 字段，
   db.py 只会在 `DB_TYPE == "mysql"` 时走 MySQL —— 双保险。
3. **Banner 注入只发生在演示实例**：`index()` 检查 `AITF_DEMO_ENABLED`，
   正式站返回的 HTML 与原来完全一致。
4. **/api/demo/* 在正式站一律 403**：`_require_demo_enabled()` 按进程级开关拦截。
5. **重置是后台任务**：任一步失败只记日志不抛异常，调度器不会崩。
