## 1. 产品概述

### 1.1 一句话定位

面向软件测试工程师的 **AI 测试闭环平台**（V5.0 由「AI 测试用例生成平台」升级）：以对话驱动的 试飞员（TestPilot） 助手为入口，自然语言描述测试需求或上传接口规格/业务需求文档，AI 自动编排解析 → 生成 → 评审 → 导出四个智能体，产出结构化、可下载的测试用例；并打通 **URL → 抓取 → 用例 → 脚本 → 执行 → 报告**的全链路自动化闭环与平台自身质量看板；支持多轮对话上下文、会话持久化回放、多厂商大模型配置、多级分类管理、思维导图在线评审。

### 1.2 产品背景

- 测试用例编写占测试工作量大头，格式 repetitive、易遗漏边界场景

- 现有 LLM 直接对话生成用例：无质量评审环节、无统一格式、不可沉淀复用、对话上下文易丢失

- 本平台将"生成用例"工程化为**对话驱动的可视化工作流**：试飞员（TestPilot） 助手自然语言交互 + 每环节独立 Agent + 质量把关 + 标准产出 + 会话持久化可回放

- 支持用户自带大模型 Key，8 家厂商开箱即用，未配模型且关闭演示模式时明确报错（演示模式 `AITF_ALLOW_DEMO=1` 可 mock 兜底）

### 1.3 产品目标

| 目标       | 衡量方式                              |
| -------- | --------------------------------- |
| 用例产出效率提升 | 一份需求描述 → 完整用例集 < 1 分钟（人工需数小时）     |
| 用例质量可控   | Reviewer Agent 评审通过才允许导出，附质量报告    |
| 开箱即用     | 未配置大模型 API Key 时自动 Mock 兜底，全流程可演示 |
| 多用户安全    | 注册/访客双通道 + 数据隔离 + 流量加密            |
| 多模型适配    | 支持主流大厂商 OpenAI 兼容协议，用户级 Key 自管    |
| 用例可评审    | 思维导图在线预览，标签化呈现类型与优先级，便于评审讨论       |
| 对话自然交互   | 试飞员（TestPilot） 助手多轮对话理解需求，上下文自动关联，会话持久化可回放    |

## 3. 功能需求

> 编号规则：FR-<模块><序号>。标注【V2.x 新增】的为对应迭代开发项。

### FR-A 身份与账户

#### FR-A1 登录

- 用户名 + 密码登录；成功后进入工作台，头部显示身份徽标

- **防暴力破解**：同一用户名连续失败 5 次，锁定 10 分钟

- 错误提示统一为"用户名或密码错误"，不暴露账号是否存在

#### FR-A2 注册

- 用户名（唯一）+ 邮箱（唯一）+ 密码

- 密码规则：≥8 位且同时含字母和数字

- **首个注册用户自动成为管理员**

- 注册成功即登录，无需二次登录

#### FR-A3 游客体验【V4.1 简化为共享账号】

- 免注册一键进入，全站共用唯一共享账号 `guest`（原「按 IP 动态建访客 / 24h TTL」已移除）

- 共享 guest **不过期、不转正、不限频**；任务上限 10 个，数据与其它访客混用

- 防滥用：共享 guest 的任务与文件由 admin 手动一键清空（`reset_shared_guest_data`），无自动 TTL 清理调度

- 首次进入自动播种示例数据（sample_seeder），开箱即可看到完整功能效果

#### FR-A4 访客转注册【V4.1 起已移除】

- 原「访客有效期内一键转正、任务与文件迁入新账户」能力随动态访客体系一并移除

- 现行行为：直接注册新账号（FR-A2）；共享 guest 数据不随注册迁移

#### FR-A5 修改密码【V2.2 新增】

- 入口：**个人中心（FR-A6）内「修改密码」按钮**

- 表单：旧密码、新密码、确认新密码

- 规则：旧密码校验错误拒绝；新密码与 FR-A2 同强度规则；两次输入需一致

- 成功后当前登录态失效，引导重新登录（保证新密码即刻生效的确定性）

- 访客不提供该入口（共享 guest 无密码）

#### FR-A6 个人中心【V2.2 新增】

- 入口：登录后点击头部身份徽标（用户名 chip）

- 展示当前账户信息：

  - 注册用户：用户名、角色（管理员/普通用户）、邮箱

  - 访客（共享 guest）：访客身份标识与共享账号说明（不过期、不转正）

- 内含操作：修改密码（FR-A5，访客隐藏）、切换账户（FR-A7）、退出登录（FR-A8）；模型配置（FR-I）自 V5.3 起升为独立一级页面（不再挂在个人中心/设置页内），用户管理（FR-F）为独立「用户管理」页（仅管理员）

- 弹窗交互：✕ 按钮 / 单击空白处 / ESC 均可关闭（均为单击触发，无需双击校验）

#### FR-A7 切换账户【V2.2 新增】

- 入口：个人中心内「切换账户」

- 行为：清除当前登录态并回到登录弹窗，可直接登录另一账户，无需二次点击

- 当前账户数据不受影响（任务/文件按账户隔离保留）

#### FR-A8 退出登录

- 入口：头部「退出」按钮及个人中心内「退出登录」

- 清除本地登录态，回到未登录视图

### FR-B 任务提交与对话交互

- **两种交互入口**：
  - **对话驱动（默认）**：首页 试飞员（TestPilot） 助手，自然语言描述测试需求，支持多轮对话上下文追问，AI 理解后自动触发生成任务；预设场景卡片一键填充（Web 登录用例 / 接口参数校验 / App 端功能 / 需求文档解析）
  - **传统表单提交**：上传规格文件（.md/.txt/.json 等）或直接粘贴需求文本，选类型 + 导出格式后提交

- **两种任务类型**：接口规格（API）/ 业务需求（business），决定用例生成策略

- **导出格式多选**：xlsx / json / xmind，任务提交前勾选

- 未登录提交 → 自动弹出认证弹窗

- 任务提交后进入工作流队列，前端实时刷新状态（对话流内联展示节点步骤与详情）

- **提交区显示当前生效模型**：如「qwen-plus · 阿里百炼」或「mock 模式（未配置）」

### FR-C 工作流执行（四 Agent 编排）

| 步骤   | Agent     | 职责                     | 失败处理              |
| ---- | --------- | ---------------------- | ----------------- |
| 1 解析 | Parser    | 提取接口/需求要素，输出结构化中间表示    | 任务置 failed，展示错误步骤 |
| 2 生成 | Generator | 按策略生成用例集（正向/异常/边界）     | 同上                |
| 3 评审 | Reviewer  | 校验用例质量（覆盖度/规范性），输出质量报告 | 同上                |
| 4 导出 | Exporter  | 按勾选格式生成下载文件            | 同上                |

- 步骤执行实时记录日志（时间、状态、摘要），前端时间线可视化

- 大模型未配置 API Key 时自动 **Mock 兜底**：流程、产物、报告完整，仅内容由规则生成器产出——保证零成本演示

### FR-D 任务管理与查看

- 任务列表：实时轮询刷新，展示名称/类型/状态/创建时间/所属分类

- **整体布局**：左侧边栏（新对话 + 历史会话列表 + 任务分类树），主区域为对话流或任务详情；对话流内联展示任务节点步骤，点击节点可展开详情

- 任务详情（右侧抽屉，不新开页面）：**3 个 Tab**（见 FR-J 详情页增强）；抽屉头部（标题 + 状态 + Tab 栏）吸顶固定，用例表格 / 思维导图等内容区独立滚动

- **数据隔离**：普通用户只见自己的任务；管理员可查看全部（`?all=true`）；越权访问返回 404 防枚举

### FR-E 导出与下载

- 支持格式：xlsx（测试管理工具可导入）、json（自动化框架可用）、xmind（脑图评审）

- 文件按任务维度存放，按用户目录隔离；下载需鉴权，禁止跨用户下载

- xmind 采用测试管理通用层级：模块 → 用例（序号.操作→预期）→ 前置/数据/步骤，类型与优先级以标签呈现

- 详情页内可直接触发导出（思维导图 Tab 导出 XMind、用例 Tab 导出 Excel）

### FR-F 管理后台（admin）

- 入口：个人中心内「用户管理」按钮（仅管理员可见）

- **统计看板**：注册用户数、活跃访客数、24h 清理数、任务总数

- **账户列表**：ID、用户名、角色、状态、任务数、注册时间

  - 禁用/启用：**禁用后下一请求即生效**（每请求回查用户状态）

  - 禁用访客 = 立即清理其全部数据（任务/日志/文件）

  - 删除：二次确认后级联删除任务、日志与文件目录，不可恢复

  - 管理员本人行显示"当前账户"，不可自禁自删

- **共享 guest 治理**（V4.1 起，独立区块）：

  - **一键清空共享数据**：清空共享 guest 名下全部任务与文件（二次确认，保留账号本身）

  - 历史遗留清理：早期动态访客体系遗留数据的「清理过期访客 / 清空全部访客 / 定向清理」接口保留，仅作迁移遗留清理用

- 无 24h TTL 自动清理调度（V4.1 起随动态访客体系移除）

### FR-G 安全与流量加密

- 认证：JWT（HS256，24h），每请求回查用户状态——禁用/删除即时生效

- **分级流量加密**：管理员明文（便于调试）；普通用户与访客的 API 流量 AES-256-GCM 强制加密，抓包不可见业务数据结构；登录/注册/访客签发为密钥分发通道（明文下发会话密钥）

- 文件上传/下载保持二进制直传（不加密）

- 密码存储：bcrypt 哈希；全链路无明文密码落库

- API Key 存储：AES-256-GCM 加密落库，接口回显脱敏（`sk-****abcd`）

### FR-H 任务分类与拖拽归类【V2.3 新增】

- **多级分类树（左栏）**：任务列表左栏展示分类树（全部任务 / 未分类 / 自定义分类任意层级），每节点实时显示任务数；分类树吸顶跟随滚动

- **分类管理**：新建（可指定父分类形成多级）、重命名、删除（子分类级联删除，其下任务自动回落「未分类」，任务本身不删除）

- **拖拽归类**：任务卡片直接拖到分类节点完成归类；拖回「未分类」即移出分类

- **拖拽移动分类**：分类节点拖到另一分类下成为其子分类，拖拽过程中目标节点高亮；移动含防环校验（不可挂到自己或子孙下）

- **点击过滤**：点击分类节点只显示该分类及全部子孙分类下的任务，可一键回到全部

- **数据隔离**：每个用户独立的分类树（访客亦然），不可见/不可改/不可归他人分类

### FR-I 模型接入配置（多厂商 LLM Provider → 多模型池）【V2.4 上线，V5.1–V5.4 收敛为模型池】

> 解决「平台只能 mock 跑」的问题：让每个用户都能在界面上配置自己的大模型 API Key，真实调用 LLM 生成用例。
>
> 落地形态：**模型配置一级页面（V5.3）** = 顶栏调度摘要（EffectiveBar，各槽池可用/冷却状态）+ 分段 Tab（admin：「我的模型 | 平台默认」）+ 每槽一张模型池卡片；后端 `app/core/providers.py`（预设）+ `app/services/llm_service.py`（OpenAI 兼容 HTTP 直连 + PoolClient 池调度）+ `app/api/llm_pool.py`（池 CRUD/排序/启停/测连通/健康 API）；管线注入点在 `app/workflow/engine.py`。

- **厂商预设（选即用）**：内置主流大厂的 OpenAI 兼容端点，选中预设后**只需填 API Key，无需手动配 Base URL**：

  | 厂商预设       | Base URL（自动带出）                                      | 典型模型                              | 备注                                               |
  | ---------- | --------------------------------------------------- | --------------------------------- | ------------------------------------------------ |
  | 阿里百炼       | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-plus / qwen-max / qwen-turbo | Token 包同端点                                       |
  | 智谱 GLM     | `https://open.bigmodel.cn/api/paas/v4`              | glm-4.5 / glm-4-flash             | 另含 **Coding Plan 专用端点** `/api/coding/paas/v4` 可选 |
  | 腾讯混元       | `https://api.hunyuan.cloud.tencent.com/v1`          | hunyuan-turbos / hunyuan-lite     | <br />                                           |
  | DeepSeek   | `https://api.deepseek.com/v1`                       | deepseek-chat / deepseek-reasoner | <br />                                           |
  | Kimi（月之暗面） | `https://api.moonshot.cn/v1`                        | kimi-k2 系列                        | <br />                                           |
  | 豆包（火山方舟）   | `https://ark.cn-beijing.volces.com/api/v3`          | 按接入点 ID 填                         | <br />                                           |
  | 自定义        | 用户自填                                                | 任意                                | 任何 OpenAI 兼容端点                                   |

  > 套餐说明：各家的 token 包 / Coding Plan 不改变接入方式——同一套 API、不同计费的 Key；仅智谱 Coding Plan 使用专用端点，已做成预设选项。

- **配置入口（V5.3 一级页面）**：侧栏「模型配置」；**每个用户独立配置**（Key 自管、用量隔离、互不可见）；admin 可额外维护**平台模型池**（对无个人池的用户生效，页内「我的模型 / 平台默认」Tab 切换）；访客只读调度摘要（配置接口 403）。

- **多模型池（V5.1，唯一配置入口）**：`text / vision / embedding` 三槽独立，**每槽可配置多条候选模型**，按优先级从上到下依次调度——某条撞限流 / 额度用尽自动切下一条，任务不中断；支持池内排序（↑↓）、启停开关、单条测连通（V5.4 起统一不带思考）、健康徽标（可用 / 冷却中 / 已停用 / 最近错误）。健康状态随行落库（`cooldown_until` / `success_count` / `fail_count` / `last_error`），重启不丢熔断记忆；同条目按 `(user_id, slot, base_url, model, key_fingerprint)` 唯一判重。**V5.4 起单条配置（每槽仅一条的旧形态）已下线**，存量 `llm_configs` 数据保留但不再参与调度。

- **配置项**：厂商预设 / Base URL（预设自动带出、可改）/ API Key / 模型名（预设建议 + 支持自由填写，如火山方舟接入点 ID）；提供「测试连通」按钮（发一条最小请求验证 Key 有效性，可复用已保存 Key 无需重复粘贴）。

- **Key 安全**：API Key 以 AES-256-GCM 加密落库（复用 FR-G 加密体系）；接口回显一律脱敏（`sk-****abcd`）；日志不落 Key；判重指纹 = sha256(Key) 前 16 位（加密带随机 nonce，不能拿密文判重）。

- **生效优先级（V5.4 纯池解析）**：个人模型池 > 平台模型池 > 服务器环境变量（老部署 `DASHSCOPE_API_KEY` 兼容）> mock 兜底。任务提交区常驻显示当前生效模型（如「qwen-plus · 阿里百炼」或「mock 模式（未配置）」）。

- **协议**：统一走 **OpenAI 兼容协议**（`POST /chat/completions`）；现有 dashscope SDK 原生调用改造为 HTTP 直连（去除 SDK 依赖，一个 client 通吃所有厂商）。Anthropic（Claude 系）messages 协议如需支持另加 adapter，列为可选二期。

- **双模型搭配（文本 + 视觉）**：除「默认模型」外，可再可选配置一个**图像识别模型（多模态）**，专用于理解技术文档 / PRD 中的截图（界面图 / 流程图 / 表格）：

  - **只配默认模型**：全流程都用它；输入含图片时图片被忽略并提示「配置图像识别模型可理解截图」

  - **两个都配**：输入文档含截图时自动两段式——①视觉模型逐图识别，输出结构化文字描述；②描述与文档文本合并后交给默认模型生成用例（推理交给更强的文本模型，视觉模型只负责"看图说话"，控成本）

  - 预设中标注支持图像输入的模型（如 qwen-vl-plus/max、glm-4v 等）；图像走 OpenAI 兼容 `image_url`（base64 data URL）格式

  - **前提**：任务输入支持 Markdown 图片引用解析（已实现：业务需求输入中的 `![](url)` / data URI / 裸贴图片 URL 会被提取，单任务上限 8 张，防跑爆视觉模型）

  - **已实现**：解析前视觉增强——图片引用被视觉模型转成「【截图解读】…」文字块合入文档，再走正常解析与生成；未配置视觉模型时忽略图片并在解析步骤摘要中提示

### FR-T LLM 接入层 LangChain 化【V3 已上线】

- **厂商自定义参数透传**：`enable_thinking`（深度思考开关）走 `extra_body`——`model_kwargs` 会被 langchain-openai 展开到请求顶层，openai SDK 的 `create()` 不认未知顶层参数（TypeError）
- **思考字段恢复补丁**：`ChatOpenAI` 官方实现只保留 OpenAI 规范字段，`reasoning_content` 等第三方非标准字段默认丢弃 → 适配层包装 `_convert_delta_to_message_chunk` 恢复进 `additional_kwargs`，思考面板行为与旧实现一致
- **兼容不丢**：端点不认 `enable_thinking` 时 400 自动去参重试 + 记忆端点（`_NO_THINKING_PARAM`）；content 分段列表归一；`<think>`/`<thinking>` 标签清理——全部平移
- **双实现回退**：`AITF_LLM_BACKEND=langchain`（默认）走 LangChain；`=httpx` 走保留的旧 `_HttpxCompatClient` 直连，一键应急回退
- **依赖**：`langchain==1.4.0` / `langchain-openai==1.6.2` / `langsmith==0.12.4`（已入 requirements.txt）

## 6. 名词解释

| 名词          | 说明                                                    |
| ----------- | ----------------------------------------------------- |
| 四 Agent     | 平台工作流的四个智能体环节：解析 → 生成 → 评审 → 导出                       |
| Mock 兜底     | `AITF_ALLOW_DEMO=1` 时由规则生成器替代 LLM 产出保证流程完整；默认 `0` 未配置模型直接报错，不再静默 mock |
| 访客（共享账号） | V4.1 起为全站唯一共享账号（`guest`，不过期/不转正/不限频），admin 手动清空共享数据，无 24h TTL 自动清理 |
| 分级加密        | 按角色决定 API 流量是否加密：admin 明文 / user+guest 强制 AES-256-GCM |
| 防枚举         | 接口对"资源不存在"与"无权限"统一返回 404，避免探测他人资源是否存在                 |
| OpenAI 兼容协议 | 行业标准的大模型 API 协议（`POST /chat/completions`），多数厂商支持      |
| MindElixir  | 轻量思维导图渲染库（120KB），支持节点标签、可编辑、零依赖                       |
| 模型池（Model Pool） | V5.1 起唯一的模型配置形态：每槽位（文本/视觉/向量）多条候选模型按优先级调度，某条限流/额度尽自动切下一条；健康状态（冷却/成功/失败计数）随行落库 |
| 平台模型池 | admin 维护的全局候选池（user_id=0），对没有个人池的用户生效；写操作仅 admin |
| 试飞员（TestPilot）助手    | 平台首页的对话式 AI 助手，自然语言交互驱动用例生成，支持多轮上下文与流式输出；**V5.9.3 起由「Buddy」更名**——"替你先把系统飞一遍"的试飞员意象，呼应探索式测试与全链路自动化定位          |
| 会话（Conversation） | 一次完整的对话流程，包含多条 user/assistant 消息，持久化可回放            |
| SSE 流式输出   | Server-Sent Events，服务端逐字推送 AI 回复，前端实时渲染，无需等待完整响应        |
| 深度思考（Deep Thinking） | 模型在给出正式回复前的推理过程（reasoning_content），以 `think` 事件流逐字推送，前端折叠展示 |
| 附件解析（Doc Extract） | 将用户上传的 docx/pdf/md 等文档抽取为纯文本，注入对话上下文供 LLM 理解 |
| Markdown 渲染管线 | `marked` 解析 + `DOMPurify` 净化的前端富文本渲染链路（XSS 安全） |
| 迭代引用 chip | 输入框上方的「🔁 基于《任务名 vN》迭代」标签，有 chip = 迭代、无 chip = 新任务；chip 上的「⚡ 生成用例」按钮才真正触发迭代 |
| 迭代链 / 版本链 | 同一任务经多次迭代形成的 `parent_task_id` 父子链，前端解析为 v1…vN 有序版本序列 |
| 版本切换器 | 详情抽屉标题行的 `vN ▾` 下拉，用于在一条迭代链的任意历史版本间切换查看 |
| MindElixir | 轻量思维导图库（见上）；其右下角工具栏已在 V2.12 迁至底栏，仅保留左上方向切换栏 |
| LangChain | 大模型应用开发框架：统一模型入口（init_chat_model）、流式调用、可观测（LangSmith）、编排（LangGraph）生态；本平台 V3 起作为 LLM 调用层底座 |
| `init_chat_model()` | LangChain 的统一模型构造入口：`model_provider` 按字符串路由厂商；8 家厂商全走 OpenAI 兼容协议 → 恒为 `"openai"`，差异只留 base_url/api_key |
| 统一 `stream()` | 全链路只用流式调用：收集模式 = 一次性完整返回（生成用例主链路），逐段模式 = 试飞员（TestPilot） 打字机事件流（think/delta/done/error）；不用 invoke |
| `extra_body` | openai SDK 官方支持的"任意厂商自定义参数"通道：`enable_thinking` 等非 OpenAI 标准参数经它透传（`model_kwargs` 会展开到请求顶层致 TypeError） |
| 思考字段恢复补丁 | `ChatOpenAI` 默认丢弃第三方厂商非标准字段（reasoning_content 等）；适配层包装内部 chunk 转换函数恢复之，思考面板行为与旧实现一致 |
| 生成子进度 | `StepLog.progress`：生成核心每处理完一个测试点回调写入「正在为第 X/Y 个测试点生成用例·已生成 N 条」，前端步骤卡实时显示 |
| LangSmith | LangChain 官方可观测平台：每次 LLM 调用产出 trace（模型/参数/耗时/Token/错误），回答"调用到底发了什么"；接入需 `LANGSMITH_API_KEY` |
| 多角色协作 | 产品 / 测试 / 开发角色以各自视角参与同一需求的用例设计；轻量版（V3.1 已上线）=角色化提示词路由，编排版=LangGraph 状态图（后续评估） |
| 全链路测试闭环 | V5.0 主线能力：URL → 抓取 → 用例 → 脚本 → 执行 → 报告全自动流水线（kind=e2e 任务，六步 STEPS_E2E） |
| 质量看板 | 平台自身 pytest + e2e 测试结果的量化看板（V5.0 M0）：汇总卡 / 文件分布 / 历史趋势，运行入口 admin 专属 |
| 被测系统（TestTarget） | 自动化闭环的被测对象登记：URL + 登录凭据（Fernet 加密，永不回传）；执行时注入登录态 |
| 执行记录（ExecutionRun） | 一次自动化执行的结构化记录：状态 / 进度 / 通过率 / report_json（每用例 outcome/error/截图）/ 自愈轮次与日志（heal_round/heal_log）/ 附属截图与录屏 |
| 自愈循环（Auto Heal） | 执行失败后的自动修复机制（V5.0 M4）：取证 → 四分类诊断 → 修脚本（断言保护）→ 备份 → 只重跑失败用例，≤3 轮收敛；修不好的归入「疑似产品缺陷」 |
| 探索式测试（Explore） | 零文档自主探索（V5.0 M5）：ReAct 循环驱动 AI 像人一样逛被测站点，边探索边产出用例；域名锁定 / 危险操作黑名单 / 三重预算收敛三重护栏 |
