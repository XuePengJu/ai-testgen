## 3. 各功能技术要点

### 3.1 对话附件文档解析（FR-N）
- **入口**：对话输入框上传 `docx / pdf / md / markdown / txt`。
- `app/api/files.py`：接收 multipart，落 `uploads/<user>/` 目录，调 `doc_extract.extract_text`，返回 `{file_id, name, ...}`。
- `app/services/doc_extract.py::extract_text` 分层抽取：
  - `.docx` → `python-docx`（正文段落 + 表格行按 ` | ` 拼接）
  - `.pdf` → `pdfplumber` 逐页抽取，跳过空白页
  - `.md / .markdown / .txt` → utf-8 读取（`errors="replace"` 容错）
  - 超大文件截断到上限（`MAX_CHARS`）
- `ChatIn.file_id` 引用附件，抽取文本 + 文件名注入对话上下文，Buddy 基于文档内容作答。
- **容错**：缺 `python-docx` / `pdfplumber` 时抛明确 `ExtractError` / `UnsupportedFormatError`，不静默降级。

### 3.2 深度思考管道与 Markdown 渲染（FR-O）
- `ChatIn.thinking: bool = True`（开关；关闭则不请求模型思考、也不展示思考面板）。
- `app/api/chat.py` 将模型 `reasoning_content` 映射为 `think` 事件，SSE 流式推送。
- 前端可折叠「思考过程」面板逐字渲染（沿用 V2.6 的 thinking 折叠交互）。
- **回复渲染管线**：`marked` 解析 → `DOMPurify` 净化 → 富文本呈现（XSS 安全）；支持代码块 / 列表 / 表格。
- 非流式兜底走同一管线。

### 3.3 用例标题复合化 + 需求摘要 + 导图布局（FR-P）
- `ensure_compound_titles`（`generator_core`）读取侧统一把标题补齐为「动作 → 预期」；详情 / 导图 / 会话回填均从数据层补全，旧任务历史标题自动对齐。
- 对话触发任务时自动从需求总结命名（任务名更可读）。
- `MindMapTab` 初始展开根节点 + `fitView` 居中自适应，首屏即见全貌。

### 3.4 NoCache 静态资源（提交 `2eca696`）
- `app/main.py` 对 `/assets` 等前端静态资源加 `Cache-Control: no-cache`，避免更新后浏览器缓存旧产物。
- `.gitignore` 规整，构建产物 `dist/` 入库（沿用 V2.8 决策：dist 入库，服务器 pull 即生效）。

## 4. 用例 ID 回归修复（重点工程故事）

### 4.1 现象
用例表格「编号」列部分为空（截图反馈）。该问题在 V2.7.1（`97c9a70`）已修复过一次，本次 React 重构后**复现**。

### 4.2 根因
上次修复含两层兜底：
1. 后端 3 个**写入点**调 `ensure_case_ids`（engine / iterate / exporter）；
2. 前端 legacy `renderCasesPane` 的**显示兜底**（存量任务缺失 ID 即时按 TC 序号补齐）。

V2.8 前端迁 React 时**只丢了前端那层**；且后端读取侧 `_parse_cases` 只调了 `ensure_compound_titles`，**没调 `ensure_case_ids`** → 存量任务 ID 列空白复现。写入侧兜底只在新任务落库时生效，**历史数据不动**。

### 4.3 三处兜底（A + B + C）
- **A 后端读取侧兜底（根治）**：`app/api/tasks.py::_parse_cases` 追加 `ensure_case_ids(obj)`。详情接口返回即补全，表格 / 搜索 / 导图 / 会话回填**全部一致**；纯读取、不改 DB、无副作用。
- **B 前端显示兜底（防御）**：`CaseListTab.tsx` 渲染前对 `cases` 内存补 ID（新增 TS 版 `ensureCaseIds`），恢复 legacy 行为；并修复空 ID 导致的 `data-case-id` 锚点重复 / 搜索失效隐患。
- **C 存量 DB 回填（清洗）**：备份 `app.db` 后，用 `PRAGMA journal_mode=MEMORY` 规避沙箱 SQLite journal 拦截，一次性回写 **9 个存量任务、30 条空 ID**（含目标 `4b9cb35c210c` 现为 `TC-001 ~ TC-014` 连续）。

### 4.4 验证
- 前端 `npm run build` 通过（tsc 无错）。
- 后端 `tests/test_case_id.py` 6 条全过；模拟 `_parse_cases` 组合逻辑（清前 3 条 → 补全）空 ID = 0。
- 全库空 ID 扫描：**0**（修复前 9 个任务）。
- 运行态：启动服务后 `GET /api/tasks/4b9cb35c210c` 返回 14 条 `TC-001~TC-014` 连续。
