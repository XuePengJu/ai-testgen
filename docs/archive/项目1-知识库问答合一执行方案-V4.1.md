## 1. 背景与问题

当前知识库页（`frontend/src/pages/KnowledgePage.tsx`）只做**知识管理**，与对话完全分离：

- 顶部导航是平级四视图：main（对话）/ knowledge（知识库）/ settings / admin
- 知识库页内四个 tab：文档 / Wiki / 图谱 / 检索测试，**全部是管理视角，没有"用知识"的入口**
- 用户要验证知识好不好用，得跳出知识库页回到首页对话，割裂

参照 WeKnora「对话为先 + 知识库为辅」的形态，目标是把**知识消费（问答）**和**知识管理**合到同一信息架构内，并打通**引用溯源**闭环。

### 已核查的现状（只读排查结论，未改动任何代码）

| 能力 | 现状 | 判定 |
|---|---|---|
| 对话基于知识库回答 | `chat.py:165 _build_rag_context` + `chat.py:216` 对所有 `POST /chat/stream` 请求**自动调用**（登录态 + 有可见库即检索，不区分首页/知识库页）；`ChatIn.kb_id`（`schemas/llm_config.py:61`）支持限定单库，不传则检索**全部可见库** | ✅ 已有（**首页生成用例对话本就自动接 RAG，只是未把引用回显**） |
| 检索测试台 | `GET /knowledge/search?q=&kb_id=&top_k=` 返回 hits + 相似度 | ✅ 已有 |
| Wiki 索引 | `POST /knowledge/bases/{kb_id}/wiki/index`、`GET .../wiki` | ✅ 已有 |
| 文档 / 分块 CRUD | knowledge.py 全套端点 | ✅ 已有 |
| 会话落库 | `conversations` + `messages` 表 | ✅ 已有 |
| SSE 协议 | 事件 `delta / think / notice / done / error` + 统一 `_sse()` 工具 | ✅ 已有 |
| 前端四个 tab | `DocsTab / WikiTab / GraphTab / SearchTab` 四个独立组件 | ✅ 已有，内容本就不同 |
| 图谱 | `GraphTab` 前端基于 documents 本地构图，**不依赖后端 graph API**；后端仅有 `graph_entities / graph_relationships` 模型（V4.1），**无 API** | ⚠️ 简版可用，真图谱待建 |
| **引用溯源** | `_build_rag_context` 只把 chunk 拼成字符串喂模型，**命中元数据未回传前端** | ❌ 缺失（核心缺口） |
| **会话区分** | `Conversation` 表无 `mode / kb_id` 字段 | ❌ 缺失 |

> ⚠️ **关键认知（2026-09-19 修正）**：RAG 不是知识库页独有，而是**全站对话的通用中间件**——首页生成用例对话同样经过 `/chat/stream` 自动检索知识库（不传 `kb_id` 时检索全部可见库）。本次改造是"把引用显式暴露 + 允许限定单库"，而非"给首页新接 RAG"。

**结论**：方案可行，后端能力约 80% 已具备；真正需要新建的只有「引用溯源通道」和「会话归属标识」。

## 2. 目标与非目标

### 目标（一期）
1. 知识库页内可直接提问，AI 基于**当前选中库**检索作答
2. 回答带**引用溯源**：显示引用来源 chip，点击跳转到对应 Wiki/文档条目并高亮
3. 知识库问答会话与首页工作流会话**互不污染**

### 非目标（一期不做）
- 真·知识图谱（LLM 实体关系抽取 API）——二期
- Wiki 在线编辑、引用片段预览抽屉——二期
- 跨库多选问答——二期
- 首页对话 **RAG 调用逻辑**：本就自动全库检索，一期**不动其检索逻辑**，仅随 `ChatPanel` 复用引用渲染（可选 props 不传即原行为），零回归
- 首页对话**是否也展示引用 chip**：待拍板（见 §9-3），默认不展示以保持零回归
- 云端部署——本地实测 + 明确授权后才执行

## 4. 详细改动清单

### 4.1 后端

#### (1) `app/api/chat.py` —— 核心改动
- **改造 `_build_rag_context`**：保持返回 `str` 不变（低侵入，不动 line 216 调用点），另用局部列表 `_rag_hits` 收集命中元数据：
  - `chunk_id`、`knowledge_id`（→ 文档/Wiki 条目）、`doc_title`、片段摘要、`score`
- **新增 SSE 事件**：在生成正文前 `yield _sse("citations", {"items": [...]})`，复用现有 `_sse()` 工具，**不动 `done` 事件结构**
- **映射链路**：`Chunk.knowledge_id → Knowledge.id / title`（Wiki 条目即 Knowledge 级）
- ⚠️ 注意：`citations` 事件对**所有** `/chat/stream` 请求都会发送（首页 + 知识库页），由前端按 mode 决定是否渲染

#### (2) `app/models/conversation.py`
- `Conversation` 增加两个**可空列**：
  - `mode: String(16) default "workflow"`（`workflow` / `kb_qa`）
  - `kb_id: String(64) nullable`
- 走 `db.py` 已有幂等列迁移，跨 SQLite/MySQL 兼容，老数据默认 `workflow`

#### (3) `app/api/conversations.py`
- 创建会话时接受并落库 `mode` / `kb_id`
- 列表接口支持 `?mode=` 过滤
- 📌 动手前先读该文件确认现有端点签名

### 4.2 前端

#### (4) `frontend/src/pages/KnowledgePage.tsx`
- tab 类型 `"docs"|"wiki"|"graph"|"search"` → 增加 `"chat"`
- 新增 `<ChatTab kb={sel} />`，图标 `MessageSquare`
- `localStorage` key `aitf_kb_tab` 兼容新值；默认保持 `docs`（待拍板）

#### (5) `frontend/src/components/chat/ChatPanel.tsx`
- 新增**可选** props：`kbId?: string`、`mode?: "kb_qa"`、`showCitations?: boolean`
- 传入 `kbId` 时：请求体带 `kb_id`、新建会话带 `mode/kb_id`
- 解析 SSE `citations` 事件并挂到消息对象
- **不传 `showCitations` 时默认不渲染引用 chip**（首页零回归）；`kb_qa` 模式显式传 `true`
- 📌 动手前先读该文件确认现有 props 与 SSE 解析位置

#### (6) 新增 `frontend/src/components/chat/Citations.tsx`
- 渲染引用 chip（标题 + 相似度 / 片段数）
- 点击回调 `onCiteClick(kbId, knowledgeId)` → 父组件切 tab + 高亮

#### (7) `frontend/src/store/chatStore.ts`
- 会话列表按 `mode` 分组：知识库问答会话只在知识库页显示

### 4.3 不动的部分（降风险）
- `SearchTab`：已接 `/knowledge/search`（hits + score），一期不动
- `GraphTab`：本地构图能跑，一期不动
- 首页对话 main 视图 **RAG 调用逻辑**：不动（本就自动全库检索）；引用渲染走 `ChatPanel` 可选 props，不传 `showCitations` 即不显示，界面零变化

## 5. 接口与数据结构

### 5.1 新增 SSE 事件 `citations`（无新增 REST 端点）

```jsonc
// event: citations
{
  "items": [
    {
      "chunk_id": "c_xxx",
      "knowledge_id": "k_xxx",   // → Wiki/文档条目，用于跳转定位
      "doc_title": "测试用例设计方法",
      "snippet": "等价类划分适用于输入域过大…",
      "score": 0.87
    }
  ],
  "kb_id": "kb_xxx",
  "top_k": 6
}
```

发送时机：**正文 delta 之前**，使前端可先显示「引用 N 篇」。
覆盖范围：对所有 `/chat/stream` 请求发送（首页对话也会收到，由前端决定是否渲染）。

### 5.2 会话新增字段

| 表 | 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| conversations | mode | String(16) | `workflow` | workflow=首页工作流；kb_qa=知识库问答 |
| conversations | kb_id | String(64) | NULL | 知识库问答绑定的库 |

### 5.3 复用（不改动）
- `POST /api/chat/stream`（`ChatIn.kb_id` 已存在）
- `GET /api/knowledge/search?q=&kb_id=&top_k=`

## 6. 验收标准

1. 知识库页切「AI 问答」提问 → 回答基于该库内容，请求体 `kb_id = 当前库`
2. 回答下方显示引用 chip，数量 = 命中 chunk 去重后的文档数
3. 点击引用 chip → 自动切到对应 tab 并高亮定位该条目
4. **回归**：首页对话提问 / 生成用例 / 历史会话**回答内容完全不变**（RAG 检索本就自动生效，本次仅新增 SSE citations 事件；首页默认不渲染引用 chip，界面无变化）
5. 知识库问答会话不出现在首页列表，反之亦然
6. `npm run build` 构建通过
7. 现有 `pytest` 用例仍全绿（引用逻辑补 1–2 条单测）
8. 本地 `uvicorn` 起服务，curl `/chat/stream` 可见 `event: citations`

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 改 `_build_rag_context` 影响调用点 | 对话上下文异常 | 用局部 `_rag_hits` 收集，不动返回值与 line 216 |
| citations 事件误影响首页 | 首页界面变化 | `ChatPanel.showCitations` 默认 false，首页不渲染引用 |
| 会话加列跨库兼容 | SQLite/MySQL 迁移失败 | 可空列 + `db.py` 幂等迁移，老数据默认 workflow |
| ChatPanel 改动波及首页 | 首页对话回归 | 新增 props 全部可选，不传即原行为 |
| 引用文本 XSS | 安全问题 | React 默认转义，禁用 `dangerouslySetInnerHTML` |
| 默认 tab 变化 | 老用户习惯 | 默认保持 `docs`，待产品拍板 |
| 首页全库检索串味 | 生成 A 用例混入 B 库内容 | 二期给首页加「检索范围」选择器（见 §9-3 / 二期） |
| 误部署 | 线上事故 | 本地实测 + 明确授权后才部署 |
