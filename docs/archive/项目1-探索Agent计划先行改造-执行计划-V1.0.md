### M1 视图指纹判重（后端，~0.5 天）

- 新文件 `app/services/view_fingerprint.py`：
  - `fingerprint(url, snapshot)` = 规范化 URL + 激活状态 + 可交互元素 `(role, name)` 有序集合
  - URL 规范化：去 fragment、去 utm/时间戳/随机 id 类噪声参数
  - 激活状态：从快照识别 `aria-selected` / active class 的 tab、菜单项名称
  - `similarity(a, b)`：Jaccard 相似度，**≥0.9 判同一视图**（不用精确 hash，防懒加载/时间戳误判）
- 集成 `app/services/explorer_agent.py`：
  - Agent 会话状态加 `visited: list[{fp, tab_triggers, clicked}]`（纯内存，单次任务内，不改 DB）
  - 每步快照后先查重；决策 prompt 注入「已见视图 + 未触发 tab 清单」
  - **循环检测**：同指纹连续 3 步无新元素 → 注入强制换目标指令
  - 「探索完」定义：该视图全部 tab 触发器点过一遍（集合覆盖）
- 开关 `EXPLORE_FINGERPRINT=1`（默认开，env 可关回旧行为）

### M2 结构化护栏（后端，~0.5 天，依赖 M1）

- **页面白名单**：e2e 任务取 crawler `pages.json` URL 集；纯 explore 任务取初始 URL 同域；越界动作拒绝并说明
- **步数预算**：核查现有 `EXPLORE_MAX_STEPS` 后复用/补齐
- 开关 `EXPLORE_GUARDRAILS=1`（默认开）

### M3 计划先行（后端 + 前端，~1~1.5 天，依赖 M1/M2）

- 后端：
  - explore 任务启动 → 新步骤「生成探索计划」（LLM 输入 = 需求 + 种子页面快照）→ 3~5 条业务流计划落盘 `out_dir/plan.json`
  - 任务进入**计划待确认**状态（优先 step 粒度暂停，不动全局任务状态机）
  - 新 API：`GET /tasks/{id}/explore-plan`；`POST /tasks/{id}/explore-plan/confirm`
  - 开关 `EXPLORE_PLAN_FIRST=1`（默认开；关闭 = 旧自由探索）
- 前端：
  - `TaskStepsCard` 新增「探索计划」确认卡：业务流勾选/删除/改标题 +「按计划探索」
  - `ExploreTimeline` 每步加「新视图 / 已见」徽章（消费 events 里的 `is_new_view`）

### M4 实时画面开关（后端 + 前端，~0.5~1 天，独立可插队）

- 后端：`GET /tasks/{id}/live-shot` → `out_dir/explore/` 最新 `step-NNN.png`（FileResponse 非 JSON 不加密，无需中间件豁免；`_own_task` 归属校验）
- 前端：`TaskStepsCard` 探索步骤 running 时「实时画面」勾选框（默认不勾 = 零开销）；勾选后 3s 轮询 blob 刷新 `<img>` + 当前动作摘要；任务结束自动停
- `frontend/src/api/client.ts` 加 `fetchTaskLiveShot(taskId)`

### M10 日志落盘 + LLM 调用记录（后端，~0.5~1 天，零侵入为主）

- 现状：全项目无任何日志文件配置；8 个 service 模块已有 logger 但根 logger 无 handler，INFO 级业务日志全部静默丢弃，后台跑 uvicorn 连 stderr 都不可见；DB 仅有 step_logs（前端进度用），LLM 调用无持久化记录
- **第 1 层：全局日志落盘（零侵入）**
  - 新文件 `app/core/logging_config.py`：`setup_logging()` = RotatingFileHandler 写 `logs/app.log`（10MB 轮转，保留 14 个备份），格式 `时间 | 级别 | 模块 | 消息`，root INFO，接管 uvicorn access log
  - `main.py` 启动时调用；`logs/` 进 `.gitignore`；`LOG_LEVEL` env 可调（默认 INFO）
  - 效果：8 个现成 logger 的 INFO 立即全部落盘，业务代码不用改
- **第 2 层：关键链路补点**
  - LLM 统一调用出口加 INFO：provider / model / 耗时 / 成功失败 / 摘要（**不记 prompt 全文**——体积与隐私）
  - 探索每步补 `logger.info`：动作 + URL + 视图指纹（step_logs 继续走 DB 不变）
  - `/chat/stream` 问答记录：user_id / 模型 / 耗时
- 新增单测：setup_logging 后日志文件生成、轮转参数生效

### M5 P0 快赢（~0.5~1 天）

- **摘要 JSON 修复**：
  - 后端：知识库文档入库时摘要字段只存纯文本（解析 `{"summary": ...}` 取值）；提供存量数据修复脚本（参照 `scripts/migrate_case_library.py` 模式，先备份表）
  - 前端：渲染兜底——摘要命中 `{"summary":` 形状时解析取值再显示
- **历史会话治理**（中栏会话列表）：
  - 标题自动取首条消息摘要（截 15 字），禁止裸「任务:07a3ee5a45a2」形态（转业务名）
  - 少于 2 轮的简短会话自动折叠进「已归档」分组（前端分组展示，可展开）
- 纯前端为主 + 一个存量脚本，无接口改动

### M6 知识库主页重构（~1 天）

- 库头：库名 + 共享徽章 + 统计（N 个文档 · N 片段 · 最近更新）
- 上传改**拖拽区**（吞掉现有「上传文档」按钮行），保留格式提示
- 文档列表重卡片 → **轻行**：类型图标（MD/PDF/DOCX/XLS/XMIND）+ 单行摘要（ellipsis）+ 右对齐元信息（片段 · 大小 · 日期）
- **状态徽章只标异常**（处理中/失败，异常行高亮），全员正常态不显示徽章
- 加搜索框 + 类型筛选 select
- 改动集中在知识库页组件，m1~m5 e2e 与知识库页无耦合

### M7 Wiki 分类降级（~0.5~1 天）

- 左侧主题分类栏 → **列表顶部筛选 chips**（全部 N / 测试需求 N / … / 未分类 N），分类标签同时渲染在每行文档名旁
- 归类时机前移：文档解析生成摘要时顺带让 LLM 打分类标签（一次调用加一个字段）；「重新生成索引」留作兜底按钮
- 「未分类 N」chip 自带「AI 归类」一键修复入口（批量补标）
- 页面从 3 栏减回 2 栏

### M8 导航收敛 + 首页驾驶舱（~1 天）

- 一级导航收敛 4 项：**AI 会话 / 用例库 / 测试中心 / 知识库**；模型配置、用户管理、被测系统、源码、系统自检沉到底部「设置」区（admin 可见性规则不变）

- ⚠️ 高风险：`.rail-btn` 等导航选择器全变 → **m1~m5 e2e 需同步改选择器**（参照 V5.5/V5.6 适配经验）

| | UI-知识库 Agent | M6 主页重构 → M7 分类降级 | 知识库页组件 + 解析打标链路 |

### 协作规则（硬约束）

1. **子 Agent 不跑 git**：改完即报，主 Agent 在合并点统一 `pytest + build + curl` 后按模块分批 commit——避免并发 commit 踩 index、避免半成品进历史
2. **同文件禁并行**：上表冲突矩阵是分组红线，波次内各 Agent 文件域零交集
3. **build/e2e 只在主 Agent 合并点跑**：子 Agent 各自跑 pytest（不同 `--basetemp`），不并发 build 同一目录
4. **每个波次结束向老板同步一次**：交付了什么、下波次启动什么
