# 记忆与个人知识库机制说明（V7.3）

> 一页讲清 ai-testgen 的「对话记忆」如何沉淀与回用。面向：新接手的工程师 / 评审者 / 部署运维。
> 配置项与部署约束见《docs/DEPLOY.md》§6.1；接口见《docs/API.md》；评估门禁见 §7。

## 1. 记忆的两层形态

ai-testgen 的记忆是**双层并行**的，两层各自独立开关、互不阻断：

| 层 | 形态 | 载体 | 强项 |
|---|---|---|---|
| **文档级**（V6.0） | 一篇人可读的 Markdown 滚动摘要（背景/关键结论/业务规则/待办） | 个人知识库文档 → Chroma 向量 | 人可读、可编辑、走标准 RAG |
| **条目级**（V7.0） | 结构化事实条目（kind/subject/content/置信度/TTL/版本链/溯源） | `memory_items` 表 + 混合检索 | 冲突裁决、时效遗忘、精确溯源、效果可评估 |

- **个人记忆库**：注册自动创建（访客引导时也保证存在），`visibility=private`、`is_personal=true`、每人至多一个（幂等建库）。文档级记忆以「文档 → 分块 → 向量」形态存在其中，用户可在知识库页看到并检索（列表置底防误删）。
- **记忆条目**：条目不进知识库页文档列表，在知识库页的**「记忆」Tab**（仅个人库显示）中可见、可改、可删、可裁决冲突。

## 2. 记忆怎么沉淀（写入）

```
对话消息落库 ──► 会话打水位标（mem_dirty / mem_last_msg_id）
                     │
                     ▼
        每晚 02:00 调度提炼（单轮限流 50 用户 × 20 会话，DB 抢占锁防多实例）
                     │
        ┌────────────┴─────────────┐
        ▼                          ▼
  文档级（V6.0 链路，不动）      条目级（V7.0，extract_facts）
  会话记忆文档（幂等覆盖）        transcript+已知主题词表 → LLM 抽取 JSON
  source_key=mem:conv:{uid}:{cid}  事实 vs 推断分档硬夹置信度
  + 每日记忆日报（mem:daily:*）     → 冲突裁决 → memory_items（幂等槽位）
        │                          │
        └────────────┬─────────────┘
                     ▼
          推进水位（失败不推进，下轮自动重试；条目链路异常只回滚自身）
```

- **水位机制**：只有新增消息才提炼；失败绝不推进水位；手动 🧠 立即整理（异步 202 + 轮询）。
- **事实抽取分档**（Python 侧硬夹，LLM 自报不可信）：用户显式声明 ≤0.95 / 明确断言 ≤0.90 / assistant 结论与 LLM 推断 ≤0.70 / **<0.5 直接丢弃**。
- **冲突裁决规则**（同 subject 槽位）：
  | 场景 | 动作 |
  |---|---|
  | 内容 Jaccard ≥0.85（语义等价） | 刷新：不建版本，置信度取 max |
  | 新置信度 ≥ 旧-0.05 | 取代：旧版 superseded（**保留可回溯**），新版 active 挂版本链 |
  | 新置信度 < 旧-0.05 | 挂起：新版 conflict（不占 active 位），待用户在「记忆」Tab 采纳/拒绝 |
  - 用户手动记忆（source=user）被覆盖时置信度虚拟 +0.2；用户手动写入无条件取代。
- **溯源**：每条带 conversation_id / message_id / evidence 原文片段，citations 可回溯到「哪句话」。

## 3. 记忆怎么回用（读取）

- **文档级**：个人库强制检索 top_k=3（`AITF_MEMORY_TOPK`），与业务库两路检索按 chunk_id 去重、记忆优先；最新日报前 800 字常驻 system。
- **条目级混合检索**（V7.2，`hybrid_search`）：
  ```
  候选 = 本人 active 条目（≤2000 条）→ 结构化过滤
  稠密通道：Chroma 余弦（⚠️ mock embedding 下整条自动关闭——假向量是噪声）
  稀疏通道：自实现 BM25（中文单字+bigram 分词，不引 jieba，双方言无 FTS）
  融合：RRF(K=60) × BM25 相关性门控(0.3+0.7·rel) —— 保留 rank 鲁棒性又恢复幅度信息
  加权：× 时间衰减 0.5^(age/半衰期) × 重要性 × 置信度（均不抹零）
  多样性：MMR(λ=0.7) 贪心去冗余（Jaccard，mock 下同样有效）→ 取 top3 注入上下文
  ```
- 命中条目自动**命中强化**（importance +0.05、hit_count+1）——越常被用到的记忆越靠前。
- **引用可辨**：citations 的 `personal=true` 标记覆盖两路命中；条目命中额外带 `memory_item_id`，前端展示「来自你的记忆 · <subject>」。

## 4. 遗忘与隐私（V7.1）

- **TTL**：todo 30 天 / fact 180 天 / preference 365 天 / rule、profile 不过期；到期 → `expired` + 让出 active 位（**不物理删**，可追溯）。
- **重要性评分**：初始 = 0.45·置信度 + 0.25·类别权重 (+0.15 用户手写) (+0.15 显式声明)；每次命中 +0.05。
- **宽限清理**：expired/deleted 超 30 天 → 夜间任务物理删行 + 清向量，**审计行永久保留**。
- **用户真删**：`DELETE ?hard=true` 立即物理删；软删走宽限期。删会话默认连带删该会话条目（`AITF_MEMORY_DELETE_CONV_ITEMS`）；删用户级联清全部条目/审计/向量。
- **审计**：所有变更（created/refreshed/superseded/conflict/expired/deleted/adopted/restored/purged）落 `memory_audits`，含前后快照与操作者。
- **访客边界**：不记忆、不入库、接口 403（沿用 V6.0）。

## 5. 附件入库（V6.0 链路，不变）

上传即登记（sha256 幂等）→ 持久副本 + 后台向量化；图片附件同步生成描述；🧠 手动整理兜底补跑漏跑附件。

## 6. 部署要点（速记）

1. **单 worker**：uvicorn 必须 `workers=1`（多进程重复触发夜间任务；详见 DEPLOY.md §6.1）。
2. **`.doc` 支持**：部署机需装 LibreOffice（soffice）或 antiword。
3. **全部开关走 `.env`**：37 个记忆相关配置项见 DEPLOY.md §6.1；把 `AITF_MEMORY_ITEMS_ENABLED` / `AITF_MEMORY_HYBRID_ENABLED` 关掉即回到 V6.0 行为（可回滚）。
4. **向量回填**：升级部署后跑一次 `python scripts/backfill_memory_vectors.py` 给存量条目补向量（幂等；mock embedding 环境自动跳过）。

## 7. 评估门禁（V7.3）

- **黄金测试集**：`app/services/memory/golden_set.json`，24 用例 = 4 场景 × 6（偏好变化 / 冲突 / 过期 / 越权隔离），种子走真实冲突裁决链路、检索走线上同一入口。
- **五类指标与阈值**：top1 命中率 ≥0.85 / 错误记忆率 ≤0.05 / 冲突率 ≤0.10 / 膨胀率 ≤8 条每会话 / 检索延迟 P95 ≤50ms。
- **跑分**：`python scripts/run_memory_eval.py`——不达标退出码 1（可挂 CI 门禁）；每次跑分落 `memory_eval_runs` 表。
- **badcase 五类归因**：extraction_miss（写入缺）/ dedupe_drift（主题漂移）/ conflict_lost（裁决失误）/ rank_miss（排序丢单）/ expired_wrong（过期误召回）+ isolation_leak（越权泄漏）。
- **线上埋点**：检索调用按 `AITF_MEMORY_LOG_SAMPLE`（默认 0.2）采样落 `memory_retrieval_logs`，供命中率与延迟观测。
