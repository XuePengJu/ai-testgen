# 记忆与个人知识库机制说明（V6.0）

> 一页讲清 ai-testgen 的「对话记忆」如何沉淀与回用。面向：新接手的工程师 / 评审者 / 部署运维。
> 配置项与部署约束见《docs/DEPLOY.md》§6.1；接口见《docs/API.md》。

## 1. 个人记忆库是什么

- **注册自动创建**：用户注册成功即自动创建（访客引导时也保证存在），命名「<用户名> 的记忆库」，`visibility=private`（仅本人可见）、`is_personal=true`，每人至多一个（幂等建库，重复触发不产生第二个）。
- **列表置底**：知识库列表中个人库固定排在最后——前端默认选中第一项，置底避免把系统维护的记忆库误选/误删为普通库。
- **它就是一个普通知识库**：记忆以「文档 → 分块 → 向量」的标准 RAG 形态存在，用户可以在知识库页看到它、检索它（但一般不需要手动管理）。

## 2. 记忆怎么沉淀（写入）

```
对话消息落库 ──► 会话打水位标（mem_dirty=有待提炼 / mem_last_msg_id=最后处理过的 Message.id）
                     │
                     ▼
        每晚 02:00 调度提炼（AITF_MEMORY_CRON_HOUR/MINUTE，单轮限流
        MAX_USERS_PER_RUN=50 × MAX_CONV_PER_RUN=20）
                     │
                     ├─► 会话级记忆文档：《会话记忆 · <会话标题>》
                     │    （source_key = conv:{user_id}:{conversation_id} 幂等覆盖，
                     │      重复提炼不产生重复文档，knowledge_bases 只有一行）
                     │
                     ├─► 每日记忆日报：《记忆日报 · YYYY-MM-DD》
                     │    （source_key = daily:{user_id}:{日期} 幂等覆盖）
                     │
                     └─► 提炼完成后回写水位（mem_last_msg_id 前移 / mem_dirty 清零 /
                          mem_at 记成功时间；失败写 mem_error，下轮自动重试）
```

- **水位机制**：只有新增消息（Message.id > mem_last_msg_id）才需要提炼，`mem_dirty` 索引加速扫描；上次提炼到哪里一清二楚，重启/错过后按 `BACKFILL_DAYS` 回填补跑。
- **幂等覆盖不膨胀**：同一会话 / 同一天的记忆文档通过 `source_key` 唯一键覆盖更新，长期使用不会产生文档堆积。
- **手动触发**：输入区 🧠 按钮可不等夜间调度，立即整理「本会话对话记录 + 本会话附件」（异步 202 + 轮询状态，见 API.md）。

## 3. 记忆怎么回用（读取）

- **个人库强制参与检索**：AI 对话时个人库恒定参与（不可取消），固定槽 `top_k=3`（`AITF_MEMORY_TOPK`）；用户额外勾选的库走另一次检索（top_k=6 / 带附件 4），两次结果按 `chunk_id` 去重（记忆优先）后汇总成一段上下文交给 AI 统一回答。
- **常驻摘要**：每轮对话在 system 提示中注入「最近一期记忆日报前 800 字」摘要（`AITF_MEMORY_SYSTEM_BRIEF=1`），让 AI 开口就带着用户的长期偏好。
- **引用可辨**：命中个人记忆的 citations 项带 `personal` 标记，前端可展示「来自你的记忆」。

## 4. 附件入库

- **上传即登记**：聊天附件（`POST /api/files`）上传时同步登记 `ChatAttachment`（sha256 幂等）并写入个人记忆库的 `Knowledge` 行（`source_key = file:{user_id}:{sha256[:32]}`，同文件重传复用不重复建行），持久副本落 `uploads/knowledge/{kb_id}/{doc_id}{ext}`（不受 24h 对话缓存清扫影响）。
- **后台向量化**：入库（分块 + Chroma 向量）由后台任务异步执行；图片附件的描述在上传请求内同步生成（多模态模型，失败不阻断上传），描述文本既是对话注入内容也是文档正文。
- **兜底重跑**：后台入库可能因重启等原因漏跑——🧠 手动整理会扫描本会话附件补跑（`ingest_pending_attachments`），状态接口的 `attachments{total, done}` 可观测进度。

## 5. 访客边界

- 共享 guest **同样有个人库**（幂等保证存在），但：
  - **不记忆**：夜间提炼跳过访客（`AITF_MEMORY_SKIP_GUEST=1`）；
  - **不入库**：访客上传附件仅做 24h 对话缓存（`AITF_FILE_INGEST_GUEST=0`）；
  - **🧠 不可用**：手动整理接口对访客返回 403。
- 删除用户时级联清理其全部知识库数据与向量（`purge_user_knowledge`），不留孤儿。

## 6. 部署要点（速记）

1. **单 worker**：uvicorn 必须 `workers=1`，多进程会重复触发夜间任务（详细原因与兜底见 DEPLOY.md §6.1）。
2. **`.doc` 支持**：部署机需装 LibreOffice（soffice）或 antiword，否则 `.doc` 上传报引导文案。
3. **全部开关走 `.env`**：不配置即默认值，零改动可用；夜间任务时间默认 02:00（Asia/Shanghai）。
