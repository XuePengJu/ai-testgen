# 录屏回放页 · 生成提示词 V1.0

> 用途：在新会话里一次性「跑 UI 端到端录屏 → 生成单文件回放页 → 展示」。
> 仓库：`/Users/xp/Documents/软件测试示例项目/ai-testgen`
> 产物：`reports/e2e-videos.html`（单文件，内嵌 15 个用例卡片 + 自动连播）

---

## 一、直接复制这段（推荐用法）

```text
在 /Users/xp/Documents/软件测试示例项目/ai-testgen 跑一次 UI 端到端测试（开录屏），
然后生成单文件「录屏回放页」reports/e2e-videos.html 并展示给我看。

请严格按下面的顺序做，别跳步骤、别自己发明命令：

【第 0 步】确认本地后端活着（这个仓库的 e2e 依赖 127.0.0.1:8005）
  curl --noproxy '*' -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8005/docs
  必须返回 200。不是 200 就先拉起服务（后台跑，别阻塞）：
  cd /Users/xp/Documents/软件测试示例项目/ai-testgen && SKIP_DEPS=1 ./start.sh
  然后轮询上面那条 curl 直到 200，再继续。

【第 1 步】清掉上次的录屏产物，避免新旧混在一起
  cd /Users/xp/Documents/软件测试示例项目/ai-testgen
  rm -rf reports/e2e-artifacts && mkdir -p reports/e2e-artifacts

【第 2 步】跑录屏（全量 15 例，约 6–8 分钟）
  env -u PYTHONPATH .venv/bin/python -m pytest tests/ui -m "e2e_ui" \
    --video=on --tracing=off --output=reports/e2e-artifacts -p no:cacheprovider -rsxX -s

  要求：
  - 必须从仓库根目录跑（--output 的相对路径是按 cwd 解析的）
  - 这条命令必须用后台方式跑，并且【不要】接 `| tail` 之类的管道（管道会缓冲到进程结束才吐输出，
    等于全程没有任何进度可看）
  - 跑的过程中每隔一段时间把「当前进度」告诉我（已跑多久 / 已经出到哪个用例），别一声不吭
  - 跑到一半我不要你重跑；如果某例失败，也先把整轮跑完再统一汇报

【第 3 步】生成回放页（一条命令，脚本自己会去拿中文用例名）
  env -u PYTHONPATH .venv/bin/python scripts/gen_e2e_video_review.py
  期望输出形如：OK .../reports/e2e-videos.html / 用例 15 / 录屏 N / 通过 X / 失败 Y

【第 4 步】展示
  把 reports/e2e-videos.html 展示出来给我（HTML 会在预览面板里直接打开）。

【汇报格式】用一张表给我：
  用例总数 / 通过 / 失败 / 跳过 / 录屏段数 / 总耗时
  失败用例逐条列出 nodeid + 中文名 + 失败原因一句话
  最后告诉我回放页里「核心主链路」那一节是不是排在最前面、业务主线用例是不是第 1 张卡

【硬性约束】
- 不要 push、不要任何 SSH 操作
- 不要改 pytest.ini 的 addopts、不要动 tests/ui 下的用例代码（只是跑和出页面）
- --tracing=off 绝对不能省（原因见下）
```

## 二、命令速查

| 目的 | 命令 | 约耗时 |
|---|---|---|
| 全量录屏（15 例，含演示 + 业务主线） | `pytest tests/ui -m "e2e_ui" --video=on --tracing=off --output=reports/e2e-artifacts -p no:cacheprovider -rsxX -s` | 6–8 min |
| 常规录屏（13 例，不含演示/业务主线） | 同上，`-m "e2e_ui and not demo and not slow"` | ~3 min |
| 只跑业务主线（真实大模型全链路） | 同上，`-m "e2e_ui and slow"` | 2.5–4 min |
| 同上，但想在界面上看 | 同上再加 `--headed` | — |
| 只重建回放页（不重跑测试） | `env -u PYTHONPATH .venv/bin/python scripts/gen_e2e_video_review.py` | <1 s |
| 只看收集结果+中文名对照 | `pytest tests/ui -m "e2e_ui" --collect-only -q --show-titles` | <1 s |
| 门禁（不含录屏，11 例） | `pytest -m "not visual and not demo and not slow"` | ~2 min |

> 命令行 `-m` 会**覆盖** `pytest.ini` 里 `addopts` 的 `-m`，所以想跑慢用例时直接给 `-m "e2e_ui"` 即可。

## 三、机制说明（供你判断输出对不对）

**回放页的数据从哪来**

| 数据 | 来源 |
|---|---|
| 用例清单 + 中文名 | `scripts/gen_e2e_video_review.py` 内部再跑一次 `pytest tests/ui -m e2e_ui --collect-only --titles-json=<tmp>` |
| 通过/失败/耗时 | `reports/e2e-report.json`（由 `tests/ui/conftest.py::pytest_sessionfinish` 落盘） |
| 录屏 | `reports/e2e-artifacts/<slug>/video.webm`，`slug` 复刻 Playwright 规则：`re.sub(r"[^0-9A-Za-z]+","-",nodeid).strip("-")` |

**卡片排序真源**：脚本里的 `SECTIONS` 常量，分三节——
`核心主链路 · 问答 → 用例生成 → 用例迭代`（业务主线排第 1）→ `知识库 · 上传与检索` → `其他 · 配置 / 统计 / 登录 / 基线`。
未收录进 `SECTIONS` 的新用例会自动落到末节，不会丢。想调顺序改 `SECTIONS` 即可，**不要**去改 nodeid / slug / 报告字段。

**为什么 `--tracing=off` 是硬性的**
`tests/ui/conftest.py` 默认 `tracing=retain-on-failure`。在本机会话的沙箱里，Playwright 写追迹产物会被无差别拒读 →
**所有用例 teardown ERROR、且一段 webm 都写不出来**（症状：断言全 ✔ 却被整批标 failed，`e2e-report.json` 也会误报）。
所以录屏跑一律显式加 `--tracing=off`。

**`@visual` 用例按设计不录屏**，所以「录屏段数」永远比「用例总数」少；`test_w2_visual_baseline` 没有 video 是正常的。

## 四、已知坑与排查

| 症状 | 原因 / 处理 |
|---|---|
| 一段 webm 都没有，用例全 failed 且 teardown ERROR | 漏了 `--tracing=off` |
| 回放页卡片里出现英文原名（如 `test_w2_visual_baseline`） | 该用例这轮**没执行**，title 需走收集期映射；确认脚本内部那次 `--collect-only --titles-json` 成功（英文名成对出现时通常是收集失败） |
| 回放页出现重复卡片 | 收集子进程 stderr 的告警行污染了 stdout 解析；脚本已加 `-p no:warnings` + 只认顶格行，若复现先查这两处 |
| `test_editor_commit.py::test_v591_edit_fix` / `test_v592_blur_commit` 偶发失败 | **既有 flaky**：改名对象是「第 N 条会话」，受前序用例新建会话的数据顺序影响；隔离单跑通过即不算回归 |
| 页面打开能显示卡片但视频播不出来 | 该用例的 `video.webm` 不在 `reports/e2e-artifacts/` 里（被清理过或那轮没跑到） |
| 业务主线用例卡在步骤⑤很久 | 正常需要等真实大模型生成（实测 90–180 s）；用例已内置「检测到失败立刻报错」，不会再黑等 |

## 五、与本提示词无关但你需要知道的两件事

1. **回放页要的是「整轮都跑过」**：`reports/e2e-artifacts/` 被清过之后，旧的回放页引用的 webm 就不存在了，
   必须重跑第 2 步整轮，页面才有完整录屏。
2. **跑长任务时别在客户端里发消息打断**：当前客户端是单任务模式，中途发消息会把正在跑的进程掐掉，
   想让它跑完就得等它自己结束。
