# DBERP 测试范围与风险（V 1.3）

> 用途：明确本次测试的边界、待澄清问题与风险，避免范围蔓延与误判。

---

## 1. 测试范围（In Scope）

| 域 | 覆盖内容 |
|---|---|
| 基础资料 | 商品、分类、品牌、单位、仓库、序列号、物流、客户/供应商及分类 |
| 采购 | 订单（审核/取消审核/验货入库）、入库单（入库）、退货单（完成/取消） |
| 销售 | 订单（确认/取消确认/发货）、发货单（确认收货）、退货（入库/不入库） |
| 库存 | 商品库存、其他出入库、盘点（确认）、库间调拨（审核）、预警 |
| 财务 | 应收/应付、收付款、核销/反核销、账龄 |
| 系统 | 管理员组权限、操作日志、打印模板、服务绑定、在线更新 |
| 接口 | 商城订单同步 API（`/api`，详见《API 接口清单》） |
| 权限 | RBAC：越权拦截、内置组保护、空权限组（详见《权限矩阵》） |

---

## 2. 不在范围（Out of Scope）

- **3.x 新增功能**：销售毛利、移动平均成本、经营工作台、查询中心、统计分析、官方付费插件（AI 助手/审批/发票等）。
- 官方插件市场付费插件（需授权，非开源功能）。
- 性能/压测、安全渗透测试（可单列专项，不在功能测试内）。
- 移动端（DBERP 1.x 为 PC 后台）。

---

## 3. 待澄清问题（需老板/业务确认）

| # | 问题 | 影响 |
|---|---|---|
| 1 | 测试基线以 **1.3** 还是 **3.x** 为准？ | 决定用例与文档是否要补 3.x 专属功能 |
| 2 | 序列号 / 批次 / 效期是**全量启用**还是仅部分商品？ | 影响 TC-BASE-05 / 库存流转用例设计 |
| 3 | 演示数据（`company_name=ERP 演示项目`）是否直接用于测试，还是重置？ | 避免断言污染、数据混淆 |
| 4 | 后台 `admin/123456` **改了没**？ | 已确认改为 `admin/admin123`（2026-09-24） |
| 5 | 商城服务（`shop_service=1`）当前是否真对接了商城？ | 决定 API/商城订单用例是否可执行 |

## 4. 风险清单

| 风险 | 等级 | 说明 | 缓解 |
|---|---|---|---|
| 版本差异 | 高 | 服务器是 1.3，官网主推 3.x；文档/UI 可能不一致 | 所有用例以实际 1.3 界面核对，不以官网为准 |
| 默认密码 | 高 | admin/123456 未改，存在越权风险（演示实例已改 admin/admin123，此项关闭） | 交付前强制改密；测试用专用组 |
| 演示数据污染 | 中 | 生产演示数据混入测试 | 明确测试库隔离 |
| 权限绕过 | 中 | 权限标识为「控制器_方法」字符串，配错易漏权 | 按《权限矩阵》逐项越权用例覆盖 |
| API 安全 | 中 | 密文/签名依赖 appSecret，泄露可伪造订单 | 接口用例含错误签名/错误密钥负向 |
| 库存并发 | 中 | 同一待入库单重复点入库可能重复增库存 | TC-EDGE-06 并发入库用例 |
| 在线更新依赖外网 | 低 | 更新需珑大服务绑定 + 网络握手 | 测试环境临时放行，记录后恢复 |

---

## 5. 退出标准（建议）

- P0 用例 100% 执行通过；P1 ≥ 90%。
- 待澄清 1/4/5 必须关闭（影响范围与环境）。
- 越权、默认密码、并发入库三类高风险用例全部覆盖。
