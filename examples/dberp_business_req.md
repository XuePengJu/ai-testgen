# DBERP 进销存系统 - 业务需求文档（测试视角）

> 用途：作为 AI 测试用例生成器的「业务需求」输入。由测试工程师根据已部署的 DBERP V1.3（生产环境 https://erp.agentest.vip/）的模块结构与核心流程梳理，用于生成覆盖采购/销售/库存/财务全链路的测试用例。
> 说明：DBERP 核心业务（采购/销售/库存/财务）**无对外 API**，均通过 Admin 后台网页（session/cookie + CSRF）操作，故以下用例以功能/业务流程测试为主。

---

## 1. 系统概述

DBERP 是一款面向中小企业的**进销存（采购-销售-库存）管理软件**，附加财务与报表能力。核心目标是实现「货、钱、账」一致：采购入库增加库存、销售出库扣减库存、每笔业务联动财务收付款、最终通过报表核对经营数据。

系统角色：系统管理员、采购员、销售员、仓库管理员、财务员（权限可配置）。

## 2. 核心业务流（主链路）

```
采购申请 → 采购订单 → 采购入库（库存+） → 采购付款（财务-）
                                      ↘ 采购退货（库存-，财务冲红）
销售订单 → 销售出库（库存-） → 销售收款（财务+）
                                      ↘ 销售退货（库存+，财务冲红）
库存盘点 → 盘盈/盘亏调整（库存±）
报表统计：采购报表 / 销售报表 / 库存报表 / 财务报表 / 利润核算
```

关键不变量（测试必须校验）：
- **库存不能为负**：任何出库/扣减操作，库存不足时应拦截或提示，不允许出现负库存（除非开启负库存参数）。
- **金额对账一致**：每笔业务产生的财务流水（应收/应付/实收/实付）之和应与业务单据金额一致。
- **订单状态机**：销售订单状态严格流转 待出库 → 已出库 → 已收款 → 已完成；不允许跨状态或回退（除非退货）。

## 3. 模块功能点

### 3.1 采购模块（Purchase）
- 采购申请单：新建/审核/驳回
- 采购订单：选择供应商、商品、数量、单价，生成订单
- 采购入库：依据采购订单入库，校验订单与实收数量
- 采购退货：对已入库生成红字单据，扣减库存
- 供应商管理：增删改查、供应商对账

### 3.2 销售模块（Sales）
- 销售订单：选择客户、商品、数量、单价，支持折扣
- 销售出库：依据销售订单出库，校验库存是否充足
- 销售退货：红字单据，回补库存
- 客户管理：增删改查、客户信用/对账
- 价格管理：客户等级价、促销价

### 3.3 库存模块（Stock）
- 商品管理：SPU/SKU、单位、成本价、售价
- 仓库管理：多仓库、库位
- 库存查询：实时库存、批次、库龄
- 库存盘点：盘盈（加）、盘亏（减）
- 其他出入库：调拨、报损、报溢
- 库存预警：低于安全库存提醒

### 3.4 财务模块（Finance）
- 收付款：销售收款、采购付款、其他收支
- 对账：应收应付明细、账期管理
- 费用管理：运费、人工等
- 利润核算：收入 - 成本 - 费用

### 3.5 报表模块（Report）
- 采购统计、销售统计、库存统计、资金流水、利润表
- 支持按时间/商品/客户/供应商维度筛选导出

### 3.6 基础数据（Company / Customer / Admin）
- 公司信息、组织架构、操作员与角色权限
- 商品分类、计量单位、品牌
- 系统参数（是否允许负库存、默认税率等）

## 4. 关键业务规则与约束（测试重点）

1. **库存扣减约束**：销售出库数量不得大于当前可用库存；并发出库需保证不超卖。
2. **价格精度**：金额计算精确到分（2 位小数），四舍五入规则一致。
3. **单据唯一性**：外部订单号（对接 API 传入的 orderSn）应幂等，重复推送不应生成重复 ERP 订单。
4. **权限控制**：非财务角色不可查看/操作财务模块；越权访问应被拦截。
5. **状态机合法性**：单据状态只允许向前流转或按规定退货回退，不允许任意跳转。
6. **数据一致性**：任意业务操作后，库存数量、财务流水、报表统计数据应保持一致。
7. **参数边界**：商品数量、金额、折扣率等输入需校验负数、0、超大值、超长字符串。

## 5. 测试关注点（供 AI 生成用例时覆盖）

- **功能测试**：各模块增删改查主流程与分支（如采购订单未审核不能入库）。
- **接口测试**（仅订单对接 API `/api`、`/other-api`）：appId 鉴权、sign 签名校验、6 个 action 的正向/异常/边界、订单幂等、解密失败。
- **异常/边界**：负库存、超卖、金额溢出、必填缺失、类型错误、超长输入、并发。
- **安全**：越权访问、sign 篡改、非法 appId、重放攻击。
- **数据一致性**：业务操作后库存/财务/报表三方对账。
- **UI/业务流程**：Admin 后台核心链路端到端（采购→入库→销售→出库→收款）。
